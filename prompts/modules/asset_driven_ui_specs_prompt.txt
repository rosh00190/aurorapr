`## ASSET_DRIVEN_UI` Module (Final English Version for Testing)**

> When the `## ASSET_DRIVEN_UI` identifier is added, the system will **automatically merge the following technical specification** into the final prompt for the code-generation AI.

---
**(Mandatory: Technical Specification for Asset-Driven UI)**
Effective immediately, you will **completely ignore** the rule for generating images via `pollinations.ai`. Instead, your sole task is to construct a creative UI using only the filenames provided in the `Keyword List` at the bottom of the master prompt, formatted as `{{img::filename.extension}}`.

**[Critical Rule: Differentiating Image Placeholder Usage]**
You **must** distinguish between the following two methods for displaying images based on their purpose. This is a mandatory rule, not a suggestion.

*   **Rule 1: 'Static' Images Must Be Hardcoded in HTML**
    *   **Definition:** Static images are elements that **do not change** after the initial page load, such as profiles, icons, or backgrounds.
    *   **Implementation:** They **must** be implemented directly within the HTML body, wrapped in a container like a `<div>`.
    *   **Purpose:** This method is for defining the fixed, structural elements of the UI.
    *   **Correct Example (HTML):**
        ```html
        <div class="profile-picture">{{img::doyoon_avatar.png}}</div>
        ```

*   **Rule 2: 'Dynamic' Images Must Be Managed by JavaScript**
    *   **Definition:** Dynamic images are elements whose content **must change in real-time** based on user interaction (e.g., clicks) or other conditions. Examples include image galleries, slideshows, or randomized displays.
    *   **Implementation:** They **must** be managed by storing the `{{img::...}}` placeholder strings in a JavaScript array or object. The image is then dynamically injected into the DOM using methods like `element.innerHTML` when an event occurs.
    *   **Purpose:** This method is for all interactive elements where the visual content is expected to change.
    *   **Correct Example (JS):**
        ```javascript
        const photoAlbum = [
          { imgSrc: '{{img::seowon_happy.jpg}}', caption: 'A happy day.' },
          { imgSrc: '{{img::seowon_sad.jpg}}', caption: 'There were days like this, too.' }
        ];

        function displayPhoto(index) {
          document.querySelector('#photo-display').innerHTML = photoAlbum[index].imgSrc;
          document.querySelector('#caption').textContent = photoAlbum[index].caption;
        }
        ```

*   **Rule 3: The Absolutely Forbidden Pattern (Crucial)**
    *   **Technical Reason:** The system processes the `{{img::...}}` placeholder by converting the entire string into a complete `<img>` tag. Therefore, placing this placeholder inside the `src` attribute of another `<img>` tag results in invalid, nested HTML (e.g., `<img src="<img ...>">`), which causes a syntax error and breaks the image rendering.
    *   **The Rule:** Under **no circumstances** should you ever use the placeholder inside an `<img>` tag's `src` attribute.
